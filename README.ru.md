# Концевики — плагин мониторинга концевиков для Candle в реальном времени

[English version](README.md)

Компактная панель Candle, которая **в реальном времени** показывает, какие
входы GRBL активны, и **предупреждает** в момент нажатия концевика: цветные
индикаторы по осям и заметная красная строка предупреждения.
При нажатом концевике панель также может предложить кнопки съезда `$T` в один
клик — для прошивки [ALOE FIXED7+](#кнопки-съезда-t-прошивка-aloe-fixed7).

```
[X][Y][Z] [P][D]      <- индикаторы входов
КОНЦЕВИК: X !         <- строка предупреждения
$T: [X-][X+]          <- кнопки съезда (только нажатые оси)
```

## Что показывает

| Индикатор | Значение |
|---|---|
| **X / Y / Z** | концевики осей: зелёный = отпущен, **красный = нажат**, серый = нет данных |
| **P** | вход щупа активен (оранжевый, информационно — без тревоги) |
| **D** | вход защитной двери: серый «не отслеживается», пока не включено в настройках (GRBL сообщает `Pn:D` только пока считает дверь ОТКРЫТОЙ и только при собранном `ENABLE_SAFETY_DOOR_INPUT_PIN`, поэтому зелёный индикатор без реального датчика был бы ложным «всё ок») |
| строка статуса | `ОК` / `КОНЦЕВИК: X Y !` / `нет статуса...` / `нет подключения` |

Дополнительно:

* входы `H`/`R`/`S` (hold / reset / cycle start) показываются текстом `Pn: ...`;
* **без устаревшей лжи**: если статус-репорты не приходят больше 2.5 с или
  порт закрыт — все индикаторы становятся серыми («нет данных»), а не
  показывают последнее известное состояние.

## Кнопки съезда $T (прошивка ALOE FIXED7+)

Пока концевик нажат, появляется блок `$T:` с кнопками **только для нажатых
осей**, парами по осям (`X-`/`X+`, `Y-`/`Y+`, `Z-`/`Z+` на отдельных строках) —
панель помещается в узкую колонку дока, даже если сработали все оси сразу. Клик отправляет `$TX-`, `$TX+`, `$TY-`, ... — команду
автосъезда форка ALOE FIXED7+: ось сама медленно съезжает с концевика на
скорости хоминга `$24` (в пределах бюджета `$29`, по умолчанию 10 мм), затем отъезжает на `$27` — всё движение
выполняется внутри прошивки, без джоггинга.

* Кнопки активны только в состоянии **Idle/Alarm** и когда не идёт отправка
  g-code программы (та же логика готовности, что у официальных плагинов).
* Из **Alarm** кнопка сначала автоматически шлёт мягкий сброс (Ctrl-X) — это
  нужно, чтобы выйти из стоковой критической блокировки `ALARM:1`,
  выбрасывающей строчные команды до realtime-сброса. `$T` уходит по **первому
  статус-репорту после того, как Candle увидел баннер перезагрузки** (то есть
  контроллер гарантированно снова жив); сторожевой таймер отменяет цепочку,
  если контроллер не вернулся, а при отпущенном за это время концевике —
  тоже отменяет.
* На **стоковом GRBL** команда безвредна: контроллер ответит `error:2`,
  движения не будет.
* Всю строку можно скрыть на странице настроек плагина.

## Как это работает

GRBL 1.1 включает поле `Pn:` в статус-репорт
(`<Idle|MPos:...|Pn:XYZ|...>`) только когда активен хотя бы один вход;
отсутствие поля `Pn:` означает, что все входы отпущены. Candle и так
непрерывно опрашивает контроллер командой `?`, а плагин получает каждый
сырой репорт через скриптовый сигнал `app.device.statusReceived` и разбирает
поле `Pn:`.

Плагин **не шлёт контроллеру собственных команд** — трафик по порту остаётся
ровно таким, каким был (исключения — `$T...` по клику на кнопку съезда и
мягкий сброс Ctrl-X первым шагом цепочки съезда из Alarm).

## Установка

1. Скопируйте папку `limit_monitor` в папку `candleplugins/` рядом с
   исполняемым файлом Candle.
2. Перезапустите Candle. Панель «Концевики» появится среди панелей (если
   скрыта — включите в меню **Вид**).

## Требования

* актуальная сборка Candle с поддержкой JS-плагинов — папка `candleplugins`
  и скриптовый сигнал `app.device.statusReceived` (актуальные исходники
  Denvi/Candle);
* **GRBL 1.1+** — формат поля `Pn:` статус-репорта, с включённым
  `REPORT_FIELD_PIN_STATE` в config.h (в стоке включено по умолчанию; если
  выключить, плагин не отличит «всё отпущено» от «не передаётся»);
* жёсткие лимиты (`$21`) **не обязательны**: `Pn:` сообщает физическое
  состояние входов независимо от настроек `$5`/`$21`/`$10`;
* кнопки `$T` полезны только с прошивкой ALOE FIXED7+ (в остальных случаях
  безвредны).

### Проверка прошивки

При каждом подключении плагин один раз шлёт `$I` и ищет в ответе метку
сборки ALOE. На чужой прошивке кнопки `$T` и цепочка Ctrl-X в Alarm
полностью отключаются — остаётся только мониторинг пинов. Пока идёт съезд
`$T`, GRBL (как и при стоковом хоуминге) не отвечает на опрос `?`, поэтому
панель показывает явное сообщение «выполняется съезд $T...» вместо «нет
статуса». Проверено с ALOE FIXED9/FIXED10.

## Настройки

Страница плагина в настройках Candle:

* **Показывать кнопки съезда $T (прошивка ALOE FIXED7+)** (по умолчанию: вкл.).
* **Отслеживать вход защитной двери (Pn:D)** (по умолчанию: выкл.) —
  включайте, только если на станке реально есть датчик двери и прошивка
  собрана с `ENABLE_SAFETY_DOOR_INPUT_PIN`; тогда оранжевый = открыта,
  зелёный = закрыта.

Хранятся в каталоге данных Candle в файле `plugin_limit_monitor.ini`
(`QStandardPaths::AppDataLocation` — доступен на запись даже при установке
Candle в `C:\Program Files`). Старый `limit_monitor/settings.ini` прежних
версий читается один раз как запасной вариант — настройки мигрируют сами.

## Разработка

Плагин — чистый QtScript + формы Qt Designer, без компиляции. Логика
(разбор статуса, конечный автомат индикации, гейты готовности `$T`,
круговорот настроек) покрыта офлайн-тестами с
заглушками API Candle, включая его поиск виджетов только среди прямых
детей:

```
node tests/harness.js
```

Русский перевод интерфейса: `translation_ru.ts` (исходник) /
`translation_ru.qm` (скомпилирован, Candle подхватывает его автоматически при
русском языке интерфейса). Пересборка:
`lrelease translation_ru.ts -qm translation_ru.qm`.
